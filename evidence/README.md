# evidence/

Everything in this directory is generated by the build that produced this repository, then re-run inside the packaged copy — not typed by hand.

| File | What it is | How to check it |
|---|---|---|
| `selftest_report.txt` | One line per tool: command, exit code, last line of output. Includes the conformance suite. | Run the same loop: `for f in tools/*.py; do python "$f" selftest; done` then `python conformance/conformance_suite.py` |
| `zm_certification_run.json` | A real certification pass over a disk manifest (doc-from-tests), plus the two metrics that came out negative and stayed negative. | `python tools/zm_certify.py selftest`, then compare the `claims` block |

Two notes on honesty, because they are the reason this file exists:

1. `zm_certification_run.json → claims.c5_poison_gate` carries both a full-build result and a `public_build_result`. Only the latter is reproducible from this repository: the public build has no L3 layer, so three latent-poison samples are *not* flagged here, and the file says so instead of showing the full-build number without its context.
2. `platform` in `selftest_report.txt` is the machine that generated it (Windows). The CI workflow runs the same suite on Linux; if a report ever disagrees with CI, believe CI.
